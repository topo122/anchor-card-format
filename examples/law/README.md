# law/ — 実例カード（日本民法・代理）

**これは Anchor Card Format v2 の書式サンプルであり、法的助言ではない。** 内容は代理（民法99条以下）の一般的な教科書レベルの記述にとどめ、具体的な事案への当てはめや結論は書いていない。

構文キーワード（`id` `tags` `ask`、および `hint` / `back` / `note` の各マーカー）は英語のまま、title・front・back・note はすべて日本語。仕様は title 以下の本文を NFC 正規化しないので（SPEC §3）、全角括弧も「」もバイト列そのままで保存される。

## 読み方

`examples/` を vault のルートと見なすと、ここのカードの deck はディレクトリ名から導かれて `law` になる。frontmatter に `deck:` キーは存在しない（SPEC §7）。ディレクトリを動かす以外に deck を変える方法はない。ファイル名は id そのもの（ULID）なので、vault の走査順＝新規カードが出題に入る順序は、そのまま作成順になる（SPEC §5, §21）。

| ファイル | 論点 | 実演している書式 |

| `01M1AHZDS8FQD17CJAXA8FT5MZ.md` | 追認（116条） | hint + back + note の三領域。back 内の `![[id]]` 参照 |
| `01M1AJ3KJG12MM3S9DCPAGFQWQ.md` | 無権代理人の責任（117条） | 番号付きリストの back、note |

## 参照カード

定義カード（`ask: false`）は出題キューに入らず、`![[id]]` の参照先としてのみ存在する。残り5枚がすべてこの1枚を参照している。参照は back の中でだけ展開され、行全体が `![[<id>]]` である行だけが参照として扱われる（文中に書くと `ref-inline` の warn になり、展開されない）。

この形にした理由は、5枚が同じ定義を共有しているから。SPEC §21 の目安どおり「2枚が3行を共有する」程度では参照カードを作らない。同じ文面をコピーして5枚に貼ると、定義を直すたびに5箇所を直すことになり、しかも直し忘れた4枚が別の内容を教え続ける。

## 意図的にやっていないこと

1. **要件の列挙を1枚に収めている。** 「3つ全部を挙げられること」が問われる以上、1要件ずつ別カードに割ると2つ思い出せた時点で正解になってしまう。答えが集合そのものであるときは、集合ごと1枚の back に置く（SPEC §21）。
2. **`reverse: true` を使っていない。** 「この定義に当たる用語は何か」という逆向きの問いは、法律用語では設問として成立しにくい（定義から条文名が一意に決まらない）。
3. **条文の全文引用・判例の射程・学説の対立を書いていない。** 1枚1問に絞るためであって、`back-too-long` の warn を避けるための省略ではない。争いのある論点を1枚に詰めると、そのカードが何を問うているのかが曖昧になる。判例を引くのは、back に書いた命題そのものの出典を note に示すときだけ（117条のカードが最判昭62.7.7 を引いているのがその例）。設問は back で完結し、note は出題されない。
